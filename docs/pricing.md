# 価格と、無料 / Pro の線引き

決定日: 2026-08-08。**広告は入れない。自動更新サブスクのみ。**

---

## 1. 決めたこと

| | |
|---|---|
| 収益モデル | **自動更新サブスクリプションのみ**(広告なし・買い切りなし) |
| 月額 | **¥300** |
| 年額 | **¥1,800**(月額の6か月ぶん) |
| 線引き | **無料は個人利用。共有を始めるときだけ Pro** |
| サブスクリプショングループ | `travelnote_pro` |
| 製品ID(月額) | `com.tsukune.travelnote.pro.monthly` |
| 製品ID(年額) | `com.tsukune.travelnote.pro.yearly` |

### 競合との比較

| | 月額 | 年額 |
|---|---|---|
| tabiori | ¥480 | ¥3,900 |
| **たびのしおり** | **¥300**(37%安) | **¥1,800**(54%安) |

サーバーを持たないので原価がほぼゼロ。**価格で正面から下回れる。**

### 広告を入れないことで守られるもの

**プライバシーラベルは「データを収集していません」。**
サーバーなし・広告なし・解析なし・課金SDKなし。決済は Apple が扱い、
開発者は購入情報を受け取らない。**開発者の管理下へ移るデータが存在しない。**

tabiori も Wanderlog も構造上言えない訴求。
**広告SDKを1つ入れた瞬間に失う。二度と検討しない。**

---

## 2. 無料でできること:個人利用のすべて

**旅の数に制限を置かない。** ひとりで使うぶんには、機能をひとつも削らない。

- **旅をいくつでも**作れる(過去の旅も残る・編集できる)
- Day タブ / タイムライン / 時刻の任意化
- 移動コネクタ / 間に合わない警告 / **リフロー**
- カテゴリ自動推定 / 外部地図リンク / 複数リンク / 持ち物 / メモ
- **しおりを取り込める**(共有された側は、何も払わずに読める・編集できる)
- **取り込んだ旅を送り返せる**

ひとり旅の人は**永久に無料で完全に使える**。
評判とレビューはここから来る。削らない。

---

## 3. Pro でできること:共有を始める

**Pro が要るのは「自分の旅の共有を、はじめて始めるとき」だけ。**

| 操作 | 必要なもの | 理由 |
|---|---|---|
| しおりを**取り込む** | **無料** | ここを有料にすると共有が死ぬ(§4) |
| 取り込んだ旅を**送り返す** | **無料** | ここを有料にすると往復が切れる |
| 自分の旅を**はじめて共有する** | **Pro** | ここが唯一の課金点 |
| 一度共有した旅を**再送する** | **無料**(解約後も) | 一度開いた扉は閉めない |

実装上は `Trip.sharedAt` が立っているかで判定する(`src/pro/entitlement.ts`)。

### なぜこの線引きが良いか

- **幹事が払い、参加者は無料。** 配りたい動機がいちばん強い人が払う
- ひとり旅ユーザーは無料で完全に使えるので、**評判が良くなり口コミが広がる**
- 受け取った人がアプリを知る → **次に自分が幹事になったとき課金する**(伝播する)
- 旅行のたびに新しい旅を作るので、**旅行のたびに Pro が要る**
  → Guideline 3.1.2 の「継続的な価値(ongoing value)」を満たす

### 審査メモに書く「継続的な価値」の説明

```
旅行のたびに、同行者と共有するしおりを新しく作成できます。
旅行の計画は繰り返し発生するため、継続してご利用いただく前提の機能です。
```

---

## 4. 絶対に有料にしないもの

**取り込み(受け取る側)。**

送られた B が「読むにはサブスクが必要です」と言われたら、
**使ったこともないアプリに課金する人はいない**ので、そこで共有が死ぬ。
B が無料で読めて編集できて送り返せることが、この機能の成立条件。

同じ理由で、**取り込んだ旅の送り返しも無料**にする。
ここを止めると A→B→A の往復が切れ、共有そのものが片道になる。

---

## 5. 解約したときの扱い

**データをロックしない。**

- 作った旅は解約後も**すべて読めるし編集できる**
- **すでに共有した旅は、解約後も送り続けられる**
- できなくなるのは **「まだ共有していない旅の共有を、新しく始めること」** だけ

理由:

1. **端末の中のユーザーのものを、支払いで開け閉めしない。**
   「データを収集していません」の思想と矛盾する
2. **旅行中に期限が切れて、同行者に更新を送れなくなるのが最悪。** これを構造的に防ぐ
3. 結果として「旅行のたびに1か月だけ入る」が許容される。
   年1回の人は年¥300、頻繁に行く人は年額¥1,800 を選ぶ。それでいい

## 6. 手数料と、回収ラインの目安

- **App Store Small Business Program に登録すると手数料が 15%**(未登録は 30%)。
  年間売上100万ドル未満が対象。**自動ではないので、申請を忘れない**
- 日本の価格は内税。消費税ぶんも差し引かれる

固定費は **Apple Developer 年99ドル(約¥15,000)のみ**。サーバーがないので他にない。
ざっくり **年額プランで年間10〜15人**、あるいは月額で相応の人数が続けば回収できる。

> 正確な手取りは Apple の計算式と為替による。**D-4 で実績を見て確認する。**

## 7. 審査の要件(自動更新サブスク)

Guideline **3.1.2**。ここを外すと確実に差し戻される。

### アプリ内(バイナリ)に必ず入れるもの

- [ ] サブスクリプションの**名称**
- [ ] **期間**(1か月 / 1年)
- [ ] **価格**、および必要なら単位あたりの価格
- [ ] **プライバシーポリシー**への機能するリンク
- [ ] **利用規約(EULA)**への機能するリンク
- [ ] **「購入を復元」ボタン**(設定 または 購入画面に、明示的なラベルで)

### App Store Connect のメタデータ

- [ ] プライバシーポリシーURL(GitHub Pages のものを設定)
- [ ] 利用規約(EULA)を、説明文またはEULA欄に記載

### そのほか

- [ ] **継続的な価値**があること(§3 の説明を審査メモに書く)
- [ ] 期間は最低7日
- [ ] **ユーザーの全デバイスで利用できること**
      → StoreKit 2 の `currentEntitlements` を見れば自動的に満たせる
- [ ] 未購入の端末で購入シートのスクリーンショットを撮る(**プロモコード配布前に**)
- [ ] **審査担当者が共有を試せるようにする。** 受け取り側は無料なので、
      審査メモに「サンプルのしおりファイル」の入手方法を書くか、
      1回だけ無料で共有できる導線を用意する

## 8. 実装方針

- **`@capgo/native-purchases`(StoreKit 2 直叩き)。RevenueCat は使わない。**
  第三者SDKを1つ入れるたびに「データを収集していません」の申告が揺らぐため
- 購入状態の判定は**端末側で完結**する(`currentEntitlements`)。
  サーバー不要 ── 「サーバーを持たない」方針とそのまま両立する
- **プラグインは静的 import**(動的importで実機が固まった前例あり)
- システムのサブスク管理画面へは `manageSubscriptions()` で飛ばす
- 判定ロジックは `src/pro/entitlement.ts` に純粋関数として置く
  (DB や StoreKit なしで検証できるように)
- **有料App契約(Paid Applications Agreement)は反映に数日かかる。**
  税務・銀行情報の登録も要るので、フェーズDの最初に着手する

### 実装前に確かめること

- [ ] Sandbox でのサブスク購入・更新・解約の挙動(**実機が要る。C-5 と同時に**)
- [ ] 期限切れの検出と、**その後も既存の旅が編集・再送できること**
- [ ] 「購入を復元」が別端末で効くこと

## 10. やらないと決めたこと

| やらないこと | 理由 |
|---|---|
| 広告 | 「データを収集していません」を失う。最大の訴求と引き換えにする価値がない |
| 買い切り | 一度きりでは維持できない。旅行は繰り返し発生するので継続課金と相性がある |
| RevenueCat | SDKを増やすとプライバシーの申告が揺らぐ。StoreKit 2 を直接叩く |
| **取り込み(受け取る側)の有料化** | 受け取った人が読めなければ、共有そのものが成立しない |
| **送り返しの有料化** | 往復が切れて、共有が片道になる |
| 無料プランでの旅の数の制限 | ひとり旅の人から取らない。評判と口コミがそこから来る |
| 解約時のデータロック | 端末の中のユーザーのものを、支払いで開け閉めしない |
| 消耗型・従量課金 | 旅程アプリに合わない |
