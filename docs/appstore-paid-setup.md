# 有料App契約・銀行口座・税務情報の登録手順

買い切り課金を出すために必要な App Store Connect 側の契約手続き。

**TestFlight 配布と無料アプリの公開には不要。** ただし銀行口座の確認や契約の
反映に数日かかるため、課金実装の前に早めに着手する。

> Apple は画面構成をよく変える。項目名が見当たらない場合は画面の指示を優先。

---

## 0. 前提

- **Account Holder 本人**でないと操作できない
- 個人アカウントの法的名称(Legal Entity)は**本名**になる

### 先に確認しておくこと

- [ ] **App Store 上の販売者名** — 個人アカウントでは本名が表示される。
      屋号で出したい場合は別途手続き(または法人アカウント)が必要
- [ ] **勤務先の副業規定** — 収益が発生するため届出の要否を確認
- [ ] **確定申告の扱い** — 金額が読めてきた段階で確認

## 1. 有料Appに関する契約を締結する

App Store Connect → **契約/税金/口座情報** → 「有料App」をリクエスト/同意。
連絡先・銀行口座・税務情報をすべて埋めると「有効」になる。
**「有効」になるまでApp内課金アイテムを提出できない。**

## 2. 連絡先情報

上級者/財務/技術/法務の担当者を設定(個人開発ならすべて自分)。
住所・電話番号はローマ字/半角。

## 3. 銀行口座

- 口座名義は**ローマ字(半角英字)**で、銀行側の英字表記と一字一句合わせる
  (表記ゆれで弾かれる)
- 売上には**最低支払金額のしきい値**があり、達しない月は繰り越される

## 4. 税務情報

### 米国税務フォーム(W-8BEN)

個人なので W-8BEN(W-8BEN-E は法人用)。

- **日米租税条約の適用を必ず申告する** — 申告しないと米国売上に
  **30%源泉徴収**される。条項番号・税率・Foreign TIN の書き方は
  画面の説明と最新の条約内容を確認(不明なら税理士へ)

### 日本の税務フォーム

画面の指示に従う。インボイス登録番号などを求められることがある。

## 5. ステータス確認

「契約/税金/口座情報」で有料App契約が**有効(Active)**になったら、
App内課金アイテムを作成できる。

## 6. 維持

- Apple の規約改定時は**再同意が必要**。放置すると配信が止まる。
  App Store Connect からの通知メールを見落とさない

## 7. App内課金アイテムの登録(契約が有効になってから)

1. App Store Connect → 対象アプリ → **App内課金** → `+`
2. 種類: **非消耗型(Non-Consumable)**
3. **製品ID: `com.tsukune.travelnote.pro`** — コード側の定数と一字一句同じに。
   **一度作ると変更・再利用できない**
4. 価格: **基準国を「日本」にしてから**選ぶ(米国基準のままだと日本価格が
   為替計算の端数になる)
5. 表示名・説明(日本語)を入力
6. 審査用スクリーンショット(価格入り購入ボタン+復元ボタンが写った購入画面)と
   レビューメモを添付 — 詳細は /iap-onetime スキル参照

### TestFlight で購入を試す

**TestFlight の課金は自動的に Sandbox になり請求は発生しない。**
Sandbox テスターの作成は不要(Xcode直インストールのビルド用)。

確認: 価格表示 / 購入後の機能解放 / 削除→再インストール→復元 /
機内モード起動で購入済み状態が保たれるか。

「読み込み中…」のまま進まない場合: アイテム作成直後(反映に数時間)/
契約が未有効 / 製品IDの綴り違い。

### 既存テスターへの配布

**プロモコード**(バージョンごとに100枚まで無料。App内課金にも使える)。
審査用スクリーンショットを撮り終えてから配ること。
