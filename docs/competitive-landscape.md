# 競合とポジショニング

調査日: 2026-08-08。数値はこの時点のもの。**再調査したら日付ごと更新する。**

---

## 1. 結論(先に)

- **「共有できる旅のしおり」では戦わない。** それは tabiori の看板であり、
  6万レビュー・★4.5・毎日更新の現役アプリに正面から挑む意味がない
- **差別化の軸は「旅行中に強い」。** 競合はどれも*計画*ツールで、出発したあとが薄い
- **獲得は日本語圏。** ただし**共有相手の言語で表示できる**道は残す(i18n の下地)
- **インバウンド特化はしない。** 理由は §4

## 2. 競合

| | tabiori | Wanderlog | Japan Travel by NAVITIME | Notion / スプレッドシート |
|---|---|---|---|---|
| 立ち位置 | 「共有できる旅のしおり」そのもの | 海外発の総合旅行プランナー | 訪日客向け総合(乗換+旅程) | 道具の流用 |
| 言語 | 日本語 | 多言語(日本語最適化は弱い) | **13言語** | — |
| 規模 | ★4.5 / **6万件**(日本) | ★4.8 / 285件(日本) | **MAU 170万** / ★4.4 | — |
| 課金 | 無料 + ¥480/月・¥3,900/年 | 無料 + ¥650〜1,800/月 | 無料 + プレミアム | 無料 |
| 更新 | 現役(調査時点で前日) | 取得できたのは2025年7月時点 | 現役 | — |
| 同時編集 | **あり** | あり | 明記なし | あり |

### 実ユーザーの不満(ここが席の空き)

**tabiori**
- **「時間入力なしで予定間に登録できない」** → 本アプリは**時刻を任意**にした
- **オフラインは閲覧のみ、編集は不可** → 本アプリは**オフラインでも編集**できる
- 「アプリがよく落ちる」→ 安定性で戦える
- 「持ち物リストで相手がチェックすると自分が入力できない」→ 同時編集の作りが粗い
- チェックリストが初期設定に戻る / デスクトップ版のUIが引き伸ばし

**Wanderlog**
- 「日本語に最適化されていない」/ Apple Maps 非対応
- ポップアップが多い / ナビゲーションが複雑 / サブスクが高い

> 本アプリの設計(docs/ux-design.md)は UX の原理から導いたものだが、
> **時刻の任意化とオフライン編集が、そのまま最大手の不満の解答になっていた。**
> 偶然だが、席が空いていることの裏づけとして扱ってよい。

### 見落としがちな真の競合

**Notion とスプレッドシート。** 「旅のしおり Notion テンプレート」で大量に出てくる。
多くの人はこれで足りている。**アプリを入れる理由**を作れないと、そもそも土俵に立てない。
→ その理由が「旅行中の運用」。Notion は旅行中に開くものではない。

## 3. 差別化(何で勝つか)

競合は全員「**計画**ツール」。出発したあとが薄い。ここに寄せる。

| 機能 | なぜ効くか |
|---|---|
| **「データを収集していません」** | 同期サーバーを持たないので言える。**tabiori も Wanderlog も構造上言えない** |
| **時刻は任意** | tabiori の名指しの不満。計画段階で手が止まらない |
| **オフラインで編集できる** | tabiori は閲覧のみ。旅先で電波がないときこそ直したい |
| **移動コネクタ + 間に合わない警告** | 「詰め込みすぎ」に計画中に気づける |
| **リフロー(ここから30分後ろへ)** | 旅程は必ず押す。競合に相当機能が見当たらない |
| **開いたら今日にいる** | 旅行中の起動導線。一覧を経由させない |
| **落ちない** | tabiori の不満。地味だが効く |

**やらない差別化**: 乗換検索(NAVITIME に勝てない)、AI旅程生成(レッドオーシャン)、
予約・決済(規模が要る)。

## 4. インバウンド特化を採らなかった理由

市場そのものは本物。2026年4-6月期の訪日消費額は **2兆5,096億円**、
1人あたり **24.4万円**、首位市場は**米国**(3,848億円/15.3%、中国を抜いた)。
広告単価の面でも魅力がある。それでも採らない。

1. **ドッグフーディングを失う** — ROADMAP のチェックポイントAは
   「自分・家族で1〜2週間使う」で成立している。開発者は訪日外国人ではない。
   個人開発で最も安く速いフィードバックループを、着手前に手放すことになる
2. **発見される導線がない** — 海外の利用者はグローバルの App Store を
   自国語で検索する。日本語 ASO は効かない。棚には NAVITIME(13言語・MAU170万)、
   Wanderlog、Google Travel、AIプランナー群が並ぶ。広告予算ゼロで割り込めない
3. **「英語を足す」では済まない** — 消費額の上位は米国・台湾・中国・韓国。
   英語だけでは大半を取り逃す。NAVITIME が13言語なのはそのため。
   翻訳・ストア掲載・レビュー返信・問い合わせが言語数だけ増え続ける
4. **訪日客の一番の痛みが旅程管理ではない** — 交通・言語・決済であり、
   そこは Google Maps / 翻訳 / NAVITIME が押さえている

### 代わりに採った筋:共有を多言語の入口にする

インバウンドを**狙わず**に、日本語ユーザー経由で外国人に届ける。

- 獲得は日本語圏(ASO が効く / 自分で使える / tabiori の不満が刺さる)
- **しおりを共有した相手の端末では、その人の言語で表示される**
- 使う場面: 外国人の友人・配偶者・親族・同僚との旅行、来日する友達を案内する
- 必要なのは**表示の多言語化だけ**。獲得の多言語化は要らないのでコストが桁で違う
- tabiori は日本語のみ。「外国人の友達と日本を回る」層はそこで詰んでいる

**そのために A-1 で i18n の下地だけ入れる**(文言をハードコードしない、
日付・時刻・通貨は `Intl` に寄せる)。着手時なら追加コストはほぼゼロ、
あとからだと全画面の書き直しになる。**将来のオプションを今のうちに安く買っておく。**

## 5. 収益モデル(2026-08-08 確定)

**自動更新サブスクのみ / 月¥300・年¥1,800 / 広告なし。**
**無料は個人利用のすべて。Pro が要るのは「共有を始めるとき」だけ。**
→ 詳細は [pricing.md](pricing.md)

判断の根拠:

- **tabiori が ¥480/月・¥3,900/年 を6万レビュー規模で成立させている。**
  この市場では課金モデルが実証済み
- **広告を入れると「データを収集していません」を失う。**
  共有をサーバーなしにしたことで得たこの訴求は、tabiori も Wanderlog も
  構造上言えない。広告収益と引き換えにする価値はないと判断した
- 買い切りではなくサブスクにしたのは、旅行が繰り返し発生する行為であり、
  一度きりの課金では継続的な開発を支えられないため

### 価格の比較

| | 月額 | 年額 |
|---|---|---|
| tabiori | ¥480 | ¥3,900 |
| **たびのしおり** | **¥300**(37%安) | **¥1,800**(54%安) |

**サーバーを持たないので原価がほぼゼロ。価格で正面から下回れる。**
これは同期サーバーを抱える競合には真似しにくい。

### 課金の線引きも差別化になる

**受け取る側は永久に無料。** 幹事が払い、参加者は登録も支払いもなしで参加できる。

- ひとり旅の人は**無料で完全に使える** → 評判と口コミがそこから来る
- 受け取った人がアプリを知る → **次に自分が幹事になったとき課金する**(伝播する)
- ストアの説明に「**相手はアプリを入れるだけ。登録も支払いも要りません**」と
  書けることが、この設計のいちばんの強み
