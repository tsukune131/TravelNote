## プライバシーラベル(Appのプライバシー)

回答: **「データを収集していません」**(広告を採用しない場合)

> 「収集」= **開発者の管理下へ**データを移すこと。判断は**組み込んだSDK込み**で行う。
> 本アプリは同期サーバーを持たず、共有はユーザー自身がファイルを送ることで行うため、
> 開発者の管理下に移るデータが存在しない。
> **これは tabiori も Wanderlog も言えない。最大の訴求なので絶対に崩さない。**

根拠(依存を足すたびにここへ戻って見直す):
- **同期サーバーが存在しない。** 共有は `.tabishiori` ファイルの受け渡し。
  送信経路はユーザーが選んだアプリで、開発者は関与しない
- **アカウント登録なし。** 氏名・メールアドレス・電話番号を取得しない
- 解析・エラー監視SDKを入れない(クラッシュは App Store Connect のレポートで見る)
- 端末内の匿名IDと表示名は端末から出ない(ユーザーが送るファイルに含まれる場合を除く)

**広告を採用した場合は、この申告が「収集しています」に変わる**
(SDK確定後、その公式ラベル案内どおりに埋める):

| データ種別 | 用途 | トラッキングに使用 | ユーザーに紐づく |
|---|---|---|---|
| 識別子(IDFA) | サードパーティ広告 | | |
| 使用状況データ(広告の表示・タップ) | サードパーティ広告・分析 | | |
| 位置情報(おおよその位置) | サードパーティ広告 | | |

> **収益額と、上の訴求を手放すことを天秤にかけて判断する(B-5)。**
> 採用する場合でも、旅程の中身は広告事業者に渡さない。

**ATT**: 「トラッキングに使用」にひとつでも該当を付けるなら、
`NSUserTrackingUsageDescription` と許可ダイアログの実装が必須。
拒否された場合は非パーソナライズ広告に切り替え、**全機能は使えるまま**にする。

年齢制限レーティング: (広告があるので「Webアクセス」「不定期な広告」等の
該当有無を確認。Kids Category には出さない)
