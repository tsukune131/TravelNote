## サブタイトル(30字以内)

検索語を詰める一等地。**名前(たびのしおり)に無い語**を入れる。

```
旅のしおりをみんなに。作りやすくひと目でわかる旅程表
```

26字。

- **アプリ名がひらがななので、ここに漢字の「旅のしおり」を入れる。**
  Apple の検索はかな↔漢字を確実には橋渡ししない。しかも**説明文は検索の
  対象外**(名前・サブタイトル・キーワードだけ)なので、説明文に何度書いても
  ASO には効かない。いちばん的中率の高い検索語なので、必ずここに置く
- 「旅のしおり**をみんなに**」が設計そのもの ── 受け取る人は登録も支払いも
  要らない。競合が言えない立ち位置がこの一文に出ている
- 打ち出すのは**見やすさ**と**作りやすさ**。UI/UX という語は使わない
  (体験そのものを書く)
- 「旅程表」と「予定表」は**役割で分ける**。意図の濃い「旅程表」をここに、
  広く拾う「予定表」はキーワード欄に置いた

> ⚠️ **単語を並べない。** 一度「ひと目でわかる旅のしおり・旅程表・旅行計画
> 店もすぐ追加」という案を書いたが、これは人が書く文ではなく単語の羅列だった。
> **枠を埋めることが目的ではない。** 23字でも言い切れているほうが強い。

## プロモーション用テキスト(170字以内)

**審査なしで差し替えられる枠。** 季節や訴求の試行錯誤はここで行う。

```
見つけたお店は、共有から放り込むだけで予定に。一日の流れは、開いた瞬間にひと目でわかります。
そして写真アルバムを紐づけておけば、旅が終わったあとも──しおりを開くたびに、あの日が戻ってきます。旅程表が、そのまま思い出になります。
```

115字。

- **上限まで埋めない。** プロモは説明文の上に出て、**折りたたみ前に見える
  数行を占有する**。170字まで書くと、いちばん練った説明文の冒頭3行が
  折りたたみの下に落ちる
- **説明文の冒頭と同じことを書かない。** 以前は「同行者と一緒に」「時刻は
  決めなくて大丈夫」「登録も要りません」が説明文とほぼ同じで、
  一等地を2つ使って伝わる情報が1つ分になっていた
- 順番は **見つける → 見る → 見返す**。最後の「旅程表が、そのまま思い出に
  なります」が、計画ツールには言えないところ ── 旅が終われば用済みの
  アプリと、終わってから開く理由があるアプリの違い
- **「Googleフォト」などの固有名は書かない**(他社商標の表記を避ける)。
  「写真アルバム」で受けて、対応先は説明文に書く

登録もパスワードも要りません。

### 組み立てで踏んだこと(直したが、書き換えるときは注意)

- **ステータスバーを切る量は px で計算する。** CSS の `%` マージンは
  **高さではなく幅**に対する割合なので、`margin-top:-5%` ではほとんど切れない
- **縦長の端末を横に2つ並べても、この縦長キャンバスは埋まらない。**
  2枚組は**重ねてずらす**(左上 → 右下に視線が動く)。左右は少しはみ出させて、
  画面の外に続いて見せる
- **キャプションの折り返しは読点で切る。** 任せると語の途中で切れる
  (「その場で放/り込む」を実際に踏んだ)

### 撮り直すときの注意

- 共有シートには**他人の名前や連絡先が写る**(上段の候補)。機内モードにするか確認する
- 開いているページは実在の店の一般的なページにする。個人のSNSは避ける
- 3枚目に写っている参加者名(あやこ)は**テスト用の名前**。確認済みなのでこのままでよい。
  撮り直すときも、実在の方の名前を入れないこと

## プライバシーラベル(Appのプライバシー)

回答: **「データを収集していません」**

> 「収集」= **開発者の管理下へ**データを移すこと。判断は**組み込んだSDK込み**で行う。
> **これは tabiori も Wanderlog も構造上言えない。最大の訴求なので絶対に崩さない。**

根拠(依存を足すたびにここへ戻って見直す):
- **同期サーバーが存在しない。** 共有は JSON ファイル(`.json`)の受け渡し。
  送信経路はユーザーが選んだアプリで、開発者は関与しない
- **アカウント登録なし。** 氏名・メールアドレス・電話番号を取得しない
- **広告SDKを入れない**(不採用を決定済み。docs/pricing.md)
- 解析・エラー監視SDKを入れない(クラッシュは App Store Connect のレポートで見る)
- **App内課金の決済は Apple が扱い、開発者は購入情報を受け取らない。**
  課金SDK(RevenueCat 等)も使わず、StoreKit 2 を直接叩く
- 端末内の匿名IDと表示名は端末から出ない(ユーザーが送るファイルに含まれる場合を除く)

**検証記録(2026-08-10・コードで確認)**

| 主張 | 確認方法 | 結果 |
|---|---|---|
| 解析・広告・課金SDKなし | `package.json` の dependencies を全列挙 | Capacitor 6 + dexie 2 + react 2 + native-purchases のみ |
| 外部通信しない | `fetch`/`XMLHttpRequest`/`WebSocket`/`sendBeacon`/`axios`/`EventSource` を `src` 全文検索 | **0件** |
| トラッキングしない | `AppTrackingTransparency`/`NSUserTrackingUsageDescription`/`IDFA` | なし |
| 権限を要求しない | Info.plist の `NS*UsageDescription` | **1つもない** |
| 輸出コンプライアンス | `ITSAppUsesNonExemptEncryption` | `false`(通信しないので整合) |
| 外部ドメイン | `src` から URL を抽出 | `maps.apple.com` / `google.com` / `tsukune131.github.io` / `tabelog.com` のみ。すべて**ユーザーが開くリンク**で、こちらから取りに行っていない |

**依存を1つでも足したらこの表に戻る。** 解析SDKを1つ入れた時点でこの申告は嘘になる。

**年齢制限レーティングの「無制限のWebアクセス」は「いいえ」**。予定に任意のURLを
貼れるが、開くのは `@capacitor/browser` = SFSafariViewController で、Safari 本体の
サンドボックスとペアレンタルコントロールが効く。自前のWebビューは持たない。

年齢制限レーティングのその他の項目は、記録と計画のみで広告もユーザー生成コンテンツの
公開も無いため「なし」。Kids Category には出さない。

**ATT は不要。** トラッキングを行わないため
`NSUserTrackingUsageDescription` も許可ダイアログも実装しない。
