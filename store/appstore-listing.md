## プライバシーラベル(Appのプライバシー)

回答: **「データを収集しています」**

> **これは広告の有無に関わらず確定する。** 同行者との共有・同時編集のために
> 旅程(ユーザーコンテンツ)を同期サーバへ送るため。
> 「収集」= 開発者の管理下へデータを移すこと。判断は**組み込んだSDK込み**で行う。

**確定分**(共有機能があるかぎり必ず申告する):

| データ種別 | 用途 | トラッキングに使用 | ユーザーに紐づく |
|---|---|---|---|
| ユーザーコンテンツ(旅程・メモ・持ち物) | Appの機能 | いいえ | |
| 識別子(端末ごとの匿名ID) | Appの機能 | いいえ | |

**広告を採用した場合に追加する分**(SDK確定後、その公式ラベル案内どおりに埋める):

| データ種別 | 用途 | トラッキングに使用 | ユーザーに紐づく |
|---|---|---|---|
| 識別子(IDFA) | サードパーティ広告 | | |
| 使用状況データ(広告の表示・タップ) | サードパーティ広告・分析 | | |
| 位置情報(おおよその位置) | サードパーティ広告 | | |

> **用途を分けて申告する。** 共有は「Appの機能」、広告は「サードパーティ広告」。
> ここを混ぜると、旅程を広告に使っていると読まれる。

申告しない側の根拠(依存を足すたびにここへ戻って見直す):
- **アカウント登録なし**。氏名・メールアドレス・電話番号を取得しない
- 共有していない旅は端末内(Dexie/IndexedDB)にのみ保存し、送信しない
- 自前の解析・エラー監視SDKは入れない
- 旅程の中身を広告事業者に渡さない

**ATT**: 「トラッキングに使用」にひとつでも該当を付けるなら、
`NSUserTrackingUsageDescription` と許可ダイアログの実装が必須。
拒否された場合は非パーソナライズ広告に切り替え、**全機能は使えるまま**にする。

年齢制限レーティング: (広告があるので「Webアクセス」「不定期な広告」等の
該当有無を確認。Kids Category には出さない)

## App内課金アイテムの「審査に関する情報」(IAPがある場合)

スクリーンショット(必須1枚): 価格入り購入ボタン+「購入を復元」が写った

```

購入画面をご確認いただけます。

購入画面までの経路: (タブ名→ボタン名)
購入の復元: (経路)
購入すると: (何ができるようになるか)
未購入でも: (既存データの扱い)
```

(日本語UIの場合は英語版メモも用意する)

> **初回提出ではIAPアイテムをアプリのバージョンに紐づけて一緒に審査に出す。**

## 審査メモ(App Review に添える情報)

```
・アカウント登録は不要です。起動後すぐにすべての機能をご確認いただけます。
・共有は招待リンクで行い、参加にもアカウント登録は不要です。
　アカウントの概念がないため、退会・アカウント削除の導線はありません。
　旅を削除すると、同期サーバー上のデータも削除されます。
・共有していない旅は端末内にのみ保存され、送信しません。
・(広告を採用した場合)広告(<広告事業者名>)を配信します。トラッキングの許可を
　求めますが、許可されない場合は非パーソナライズ広告に切り替わり、機能制限はありません。
・(HealthKit等の権限の用途: 読み取り/書き込みそれぞれ何のためか、
　広告・第三者提供に使わない旨)
・(医療系の免責)
```
